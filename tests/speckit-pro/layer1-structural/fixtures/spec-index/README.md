# Fixtures: spec-index generator

Committed fixture spec trees consumed by
`tests/speckit-pro/layer1-structural/validate-spec-index-helper-contract.py`
(the `determinism/` tree) and `tests/speckit-pro/unit/test-generate-spec-index.py`
(every other tree). These are **test inputs
only** — no production code lives here.

The lifecycle determinism self-test copies `determinism/` into its own temporary
Git repository and adds the fixture files to that repository's index. It does
not borrow the enclosing checkout's Git metadata or user/system configuration.
The read-only check must preserve both fixture and Git metadata bytes; temporary
state is removed afterward. This test-owned repository does not qualify copying
or synthesizing Git state for verification of a user's existing worktree.

**Sentinel spelling.** Every tree except `current-canonical/` keeps the legacy
spelling `regenerated by generate-spec-index.sh` in its generated-zone sentinels.
That is deliberate: it is the input a repository written by an older release
carries, and the generator must migrate it. The runner's canonical spelling, and
the one every shipped template uses, drops the `.sh`: `regenerated by
generate-spec-index`. `current-canonical/` is the one tree that starts in the
canonical spelling, so the current form is exercised as a committed input and not
only through a runtime string replace. Do not hand-migrate the legacy trees.

The generated zones use this exact byte framing: one blank line before
`GENERATED:INDEX:START`, one blank line between each zone, an empty zone is its
`START`/`END` lines on consecutive lines with no body between them, and the file
ends with `GENERATED:BACKLINKS:END` + a single trailing newline.

## Fixture cases

| Dir | Case | Behavior under test |
|-----|------|------------------------|
| `current-empty/` | Version-marked MOC, all three zones present-but-empty, NO sibling artifacts, no `prs.json`. A regen reproduces all-empty zones → zero diff → `--check` exit 0. | Current-path no-op |
| `stale-fill/` | Version-marked MOC with empty zones BUT sibling stub artifacts + a populated `.process/prs.json`. A regen fills BACKLINKS + PRS → non-empty diff → `--check` exit 1. Also the ordering fixture (≥2 precedence buckets + `.process`). | Present-zone rebuild, stale path, and ordering |
| `inject-missing-all/` | Version-marked MOC with NO zone markers at all and sibling stub artifacts. Inject-if-missing adds the three empty zones at the canonical anchor, then fills them. | Inject-if-missing |
| `skip-one-missing/` | Version-marked MOC with ONLY the PRS marker pair removed (INDEX + BACKLINKS present); sibling artifacts present. The missing PRS zone is skipped; INDEX + BACKLINKS are still rebuilt. | Skip one missing zone |
| `prs-malformed/` | Version-marked MOC + a `.process/prs.json` containing invalid JSON. Fail-safe: exit 2, distinct from missing data. | Malformed PR data |
| `current-canonical/` | Same shape as `current-empty/` (all three zones present-but-empty, no sibling artifacts), but the sentinels use the canonical spelling. A check exits 0 and leaves the tree byte-identical. | Canonical spelling is current (`ValidateSpecIndexCanonicalSpelling`) |
| `atomicity/` | Three specs under one root: a good gated map (`a-prsg-913-good`), a legacy non-gated map (`b-prsg-914-legacy`), and a gated map whose BACKLINKS marker pair is unbalanced (`c-prsg-915-poison`). A write must exit 2 and leave every map byte-identical, including the good one. | All-or-none batch (`test_unbalanced_marker_aborts_the_batch_without_writes`) |
| `determinism/` | Three specs: a current map (`a-prsg-910-current`), a stale map with sibling artifacts and a populated `.process/prs.json` (`b-prsg-911-stale`), and a legacy non-gated map (`c-prsg-912-legacy`). The helper-contract suite copies it into its own Git repository, runs the read-only check, and requires exit 1 with unchanged bytes. | Read-only check on a tracked tree (`ValidateSpecIndexDeterminism`) |
| `roadmap-moc/` | Two roadmap-MOC home notes at `docs/ai/specs/`: `myproject-roadmap-MOC.md` and `otherproject-roadmap-MOC.md`, each carrying ONLY the INDEX sentinel pair (gated). Under `specs/`: `prsg-001-foo` (status `complete`), `prsg-002-bar` (empty `status`), `prsg-003-noid` (gated, `spec_id` present but empty), `prsg-010-baz` (status `in-progress`), all owned by `myproject`; `prsg-004-other`, owned by `otherproject`; `legacy-thing`, a non-gated dir; and two flat dirs with only a `spec.md`, `prsg-011-flat-owned` (its `up:` names the `myproject` roadmap) and `prsg-099-flat` (no ownership metadata). Each home INDEX is populated from the repository scan with one row per gated spec that home owns (non-empty `spec_id`, normalized-ID ascending, relative `[]()` links, `spec.md` fallback rows for flat specs the home owns); the empty-`status` spec still emits a row with a blank status; the empty-`spec_id` spec, the legacy dir, `prsg-099-flat`, and specs owned by the other home are skipped; every per-spec SPEC-MOC INDEX stays empty/byte-identical. | Home-note index behavior (`test_write_populates_home_indexes_without_rewriting_current_spec_maps`) |

`SPEC-MOC.md` is the map note itself and is therefore NOT one of its own
BACKLINKS rows.
This is what lets `current-empty/` (only a `SPEC-MOC.md`, no artifacts) regenerate
to an all-empty, zero-diff map.
