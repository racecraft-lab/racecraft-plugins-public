# Roadmap Knowledge Map and MOC Compatibility View

The durable roadmap map lives at
`docs/ai/knowledge/projects/<roadmap-slug>/roadmap.md`. It is an OKF concept
that owns the reviewed epic grouping, rationale, and links. Generated project
and spec indexes provide progressive disclosure.

`docs/ai/specs/<roadmap-slug>-roadmap-MOC.md` remains during the v1 transition
as a generated compatibility view for existing tools and links. It is no longer
an independent curation surface.

## Ownership

| Surface | Owner | Edit by hand? |
|---|---|---|
| Canonical `roadmap.md` grouping and rationale | Maintainer through a reviewed knowledge plan | Only through the reviewed source/plan flow |
| OKF `index.md` files | `knowledge-update-apply` | No |
| Legacy roadmap-MOC body and frontmatter | `knowledge-update-apply` compatibility renderer | No |
| Technical-roadmap status/catalog | Technical roadmap and workflow owners | Yes; this remains the catalog authority |

To change epic grouping or rationale, update the authoritative roadmap source
and review a same-path replacement from `knowledge-update-plan` action
`supersede`. Apply that exact plan with its plan object, hash, and expected
snapshot. Use `rebuild` only when canonical sources are current and a generated
projection drifted. Never edit either generated index or the MOC compatibility
view.

## Compatibility zones

The legacy view retains familiar sentinel-bounded zones so older consumers can
continue reading it:

```text
<!-- GENERATED:INDEX:START (do not edit; regenerated by knowledge rebuild) -->
- [PRSG-001](../../../specs/prsg-001-foo/SPEC-MOC.md) · complete
<!-- GENERATED:INDEX:END -->
```

All zones, including the formerly curated epics zone, are projections from the
canonical concept and current authorities. Links remain relative Markdown
`[]()` targets. Rows are deterministic and normalized-ID ordered. A second
rebuild with unchanged sources is a byte-identical no-op.

`generate-spec-index-check` and `generate-spec-index-write` remain temporary
response-compatible adapters. New flows use `knowledge-health`,
`knowledge-update-plan`, and `knowledge-update-apply`.

## Advisory epic count

About ten top-level epics remains a navigability guideline, not a gate. Warn
when the reviewed grouping exceeds it, but do not reject, silently regroup, or
change the canonical concept.

## Migration

For an existing hand-curated roadmap-MOC, action `migrate` proposes moving its
curated grouping and rationale into the canonical roadmap concept while
preserving the original file as evidence until apply. The apply records the
cutover, renders the compatibility view, and never deletes unmatched content.
Review unmatched or ambiguous material rather than inventing rationale.
