Design simulation — no real approval authority or security qualification

Every reviewer, machine, input, digest label, evidence reference, status response, record, and task is synthetic. Clicking a button does not prove human presence, enroll a credential, sign anything, or authorize real implementation.

Workflow state stays in memory. No credentials, real signing, service setup, or production runner access. The canonical gallery head saves only theme preference and requests its standard fonts; fonts have an offline fallback.

Question and scope

Can one frozen planning bundle carry separate finding decisions and a final confirmation, while later admission and every task use still refuse stale inputs, lost trust, or unavailable current status?

This explores ADRs 0013 and 0015. One reviewer is modeled. First signer candidate: Secure Enclave; fresh biometric or password confirmation (unqualified). The model treats the signer as opaque. Protected enrollment, status transport, isolation in the existing macOS account, encoding, and human qualification remain unresolved. Another machine is unavailable; transfer here is simulated only.

The Prototype tab contains the main review flow. This tab contains walkthroughs, fault controls, the complete frozen bundle, and state inspection. Switching views preserves all state.

Limit: a passing modeled path demonstrates only these interface transitions. It cannot establish protected capture, signer custody, current authentication, rollback resistance, independent enrollment, faithful protected presentation, host parity, or a safe real task route.
