        About this simulation
        
      
        No real approval authority or security qualification
        Every reviewer, machine, input, digest label, evidence reference, status response, record and task is synthetic. A button cannot prove human presence, enroll a credential, sign anything or authorize real implementation.
        
      
        Question
        
      
        Can a reviewer understand the frozen plan, make each residual-finding decision, then explicitly confirm it while later use refuses changed inputs, lost trust or unavailable current status?
        
      
        Setup and use
        
      
        Open this single HTML file. In Review, read the plan, decide both findings and check your choices before confirming. Implementation is separate. Scenarios contains guided cases, invalid actions and full diagnostics.
        
      
        Workflow state stays in memory. The canonical gallery head saves only theme preference and requests its standard fonts, with an offline fallback. This file accesses no credentials, real signer, service or production runner.
        
      
        Unqualified boundary
        
      
        This explores ADRs 0013 and 0015 with one synthetic reviewer. First signer candidate: Secure Enclave; fresh biometric or password confirmation (unqualified). The model treats signing as opaque. Protected enrollment, current-status transport, isolation in the existing macOS account, encoding and human qualification remain unresolved. Another machine is unavailable; transfer is simulated only.
        
      
        A modeled pass shows interface transitions only. It cannot establish protected capture, signer custody, current authentication, rollback resistance, independent enrollment, faithful protected presentation, host parity or a safe real task route.
