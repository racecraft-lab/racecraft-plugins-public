## How to read this record

The mirror-membership block enumerates the complete new contract surface in eight
categories. Nothing is left implicit.

| Category | What it holds | Source |
| --- | --- | --- |
| 1 | Contract documents by `$id`, `schema_version`, and committed-bytes SHA-256 | derived |
| 2 | Declared members: every object's property set and `required` subset, by JSON Pointer | derived |
| 3 | Closed enumerations: every `enum` and `const` with every one of its members | derived |
| 4 | Stable identifiers | derived |
| 5 | Bindings into frozen CAR-003 contracts | derived |
| 6 | Frozen numerics with unit and comparison direction | derived |
| 7 | Decision semantics that add no schema member | authored |
| 8 | Enforcement guards | authored |

**Categories 1 through 6 are derived, never transcribed.**
`tests/speckit-pro/unit/test-twin-handoff-completeness.py` re-derives them from the
committed schema documents, frozen instances, and partition registry entries and
diffs against the block in **both** directions: a delivered member missing from
the record fails, and a recorded member absent from the artifacts fails too. So
the completeness claim is machine-verified rather than attested, and the way to
re-issue this record after any artifact change is to run that check and answer
every difference it names. [FR-034a, SC-011]

**Addressing.** Schema members are addressed as `<document $id>#<JSON Pointer>`.
Members of a frozen instance are addressed as `<document identity>#<JSON Pointer>`,
where the identity is the instance's own `registry_id`, `comparison_id`, or
`fixture_kind` — never a repository path, because your copies sit elsewhere. A
category 3 entry names the closed value set once and lists every site that
declares it, so 56 sites carrying the same three-member response enum are one
member with 56 sites rather than 56 members.

**`hash_relevant`** answers FR-002: is this member inside a CAR-004 content
address? Every declared member of the registry document and the comparison
document is, because FR-002c addresses each whole document under the single
FR-002a preimage rule — SHA-256 over canonical JSON with the record's own digest
member, and only that member, removed. The exceptions recorded here are the schema
documents themselves and their `$id` URIs (a schema document is bound by the
file-bytes digest of FR-004, which is deliberately not the FR-002a record
preimage), the two partition registry entries (content-addressed by the frozen
CAR-003 builder over their objective set, not by CAR-004), and the authored
category 7 and 8 entries, which add no schema member at all.

**`mirror_obligation`** is exactly one of three, and every entry carries exactly
one. An entry with none, or with more than one, is rejected.

- `mirror_required` — carry this member, with this shape, on your side.
- `car_owned` — CAR-004 owns it and you owe nothing. Every category 4 identifier
  is `car_owned`: the literals live in the CAR-004 and CAR-011 namespaces and you
  mint your own under G56R-004 and G56R-011. The obligation to *have* a registry
  key, a control id, and a topology id is carried by the category 2 entries that
  declare them required, which are `mirror_required`.
- `sanctioned_divergence` — exactly one member, described below.

None of the three is a reconciliation candidate, so every entry in this record is
publishable as it stands. [FR-036a]

## Category 7 — decision semantics that add no schema member

These are the rules two conforming implementations must both adopt to reach the
same verdict on identical evidence. None of them adds a schema member, which is
exactly why they need this section: CAR-003 proved that a schema-shaped handoff
loses them.

### 7.1 Adaptive signal-to-response mapping is total

Every member of every observed signal set resolves to exactly one response drawn
from `escalate`, `hold`, `non_scorable`. The four maps are set-equal to their
frozen sources: the terminal-state map to the frozen terminal-state enum, the
plane map to the frozen `failure_plane` enum, the code map to the frozen
`failure_code` enum, and the retry-count and budget-threshold rules to their
declared direction-and-threshold pairs. A signal that resolves to more than one
response is rejected. [FR-010]

### 7.2 Row-resolution precedence

A row usually carries several signals at once. The precedence over the closed
five-member source set is frozen as the ordered array

```text
failure_code > failure_plane > retry_count > budget_threshold > terminal_state
```

and the always-valued terminal state ranks last, so it never masks a more specific
signal. Resolution takes the response of the highest-ranked source the row
actually carries. [FR-010a]

### 7.3 and 7.4 The two map-consistency rules

Two consistency rules bind the maps to frozen CAR-003 artifacts rather than to
literals restated here.

1. **Plane map against the frozen plane derivation.** The plane a code belongs to
   is derived live from `claude_score_bundle.py`, not transcribed. The plane map's
   response for a plane must agree with the code map's response for every code in
   that plane. [FR-010b]
2. **Terminal-state map against candidate-plane pairing.** Each terminal state is
   paired with its candidate-plane code, derived live as `candidate_<state>`, and
   the two maps must agree on the pair. A derived code absent from the frozen
   `failure_code` enum is a failure, not a silent skip. [FR-010c]

Deriving both rules live means a future joint change to a mirrored enum surfaces
as a CAR-004 or G56R-004 totality failure rather than as a silently changed
verdict.

### 7.5 The ordered route sequence

`escalation_ladder` is a declared array whose order is preserved and never sorted:

```text
model-alpha__medium -> model-alpha__high -> model-beta__high
```

"Next-higher qualified route" means the next entry in that array, and nothing
else. At the ceiling there is no next route, so the caller records no escalation
and refuses to wrap around; at the floor a due de-escalation records no step and
no wrap-around while the streak still resets. Every ladder entry is an admitted
tuple of the bound successor-capability freeze, appearing exactly once, with a
within-model pair never contradicting the frozen effort ladder and every
cross-model step carrying a recorded rationale. [FR-011a, FR-011b]

### 7.6 Clean-pass streak accounting

A clean pass is `terminal_state: completed`, `failure_code: none`, zero retries,
and no budget trigger met. De-escalation is decided only between objectives, never
mid-objective, and requires a streak of three. The accounting rules are:

- An escalating objective never counts toward the streak.
- A `non_scorable` objective neither advances nor resets it, and the streak
  resumes across it; that disposition outranks the reset a non-clean row would
  otherwise cause.
- Reaching three resets the counter at that boundary whether or not a step
  actually occurs, so the ceiling and the floor cannot accumulate credit.

[FR-012, FR-012a]

### 7.7 Bound scope and breach outcomes

Every retry and cancellation bound declares the scope it is counted over and the
terminal state and candidate-plane failure code it records on breach. The frozen
values: retry and cancellation bounds are counted `per_objective` for the unpinned
and adaptive controls and `per_unit` for the orchestration-changing control; a
retry-bound breach records `failed` with `candidate_failed`, and a
cancellation-bound breach records `cancelled` with `candidate_cancelled`. An
escalation resets neither counter. A bound counted over a scope other than its
declared one is a failure. [FR-014, FR-014a]

### 7.8 The platform-initiated reroute observable

A platform-initiated route change is identified by the already-frozen
`service_reroute` failure code, not by a new member. It consumes no escalation
allowance, resets no clean-pass streak, and — appearing anywhere in an
orchestration unit, on the parent or on any child — makes the **whole unit**
non-scorable rather than being folded away by aggregation. [FR-015a]

### 7.9 Unit membership and its agreement with the frozen parent-child graph

An aggregation unit is one parent objective plus the children it spawned. A row
joins the unit by being the parent's own row or by carrying an authored spawning
identifier; a member recording no terminal state is a failure, not an omission.
Where a member's evidence binds a frozen `parent_child_graph`, the induced
membership must agree with it, and the unit may not exceed the declared fan-out
ceiling of two. [FR-016d, FR-017a]

### 7.10 Parent-plus-children aggregation

Every dimension the frozen Pareto rule reads is aggregated over the whole unit by
the declared rule:

| Dimension | Rule |
| --- | --- |
| `input_tokens`, `cached_input_tokens`, `output_tokens`, `duration_ms`, `retries`, `compactions` | `sum` |
| `terminal_state` | `worst_wins_by_severity` over the frozen order `completed`, `failed`, `timed_out`, `cancelled`, `budget_exhausted`, `abandoned` |
| `acceptance` | `parent_objective_oracle` |

An `aggregation_rule` omitting a dimension is a failure, and a severity order not
set-equal to the frozen terminal-state enum is a failure. [FR-016, FR-016a]

### 7.11 Acceptance-floor precedence

On a unit that failed before reaching its oracle, the acceptance floor of zero
outranks the null-acceptance allowance: an aggregate acceptance may not be
non-zero while the aggregate terminal state is anything other than `completed`.
The floor is the stricter rule and wins. [FR-016b, FR-016c]

### 7.12 Raw-token and cache aggregation

The raw-token vector sums four members — input, cached input, output, and
`reasoning_output_tokens`. The reasoning member is summed and reported but never
enters the dominance comparison, the raw-token identity, or the quantity the
`raw_token_ceiling` is read against; that quantity is the three bounded members
alone, and they sum to the ceiling exactly. Each cache quantity is read against
the ceiling keyed to it — cache read against `max_cache_read_tokens`, cache write
against the same closed TTL class space — and never against `max_input_tokens`.

When a unit member records no cache diagnostic, the quantity is reported
**unobserved**, never zero. A zero would claim a measurement nobody made and would
silently satisfy a ceiling. [FR-016e, FR-030b]

### 7.13 Smoke-bound scope and the elapsed wall clock

Every smoke bound is counted over the parent-plus-children unit, not over the
parent alone. The thirty-minute cap is read as **elapsed wall clock**, never as the
additive `duration_ms` the aggregation rule sums, because a two-child parallel
dispatch sums to more wall time than it takes. A child dispatch consumes no
objective attempt: the five-attempt bound counts objectives, not dispatches. A run
that reaches a bound stops at the bound and remains valid non-scored evidence.
[FR-030, FR-030b]

### 7.14 The read-back rule and the three exact-treatment observables

Every observable is read back from the evidence the run produced, never from the
dispatch request. Asking the request what it asked for demonstrates nothing.

| Control | What makes it demonstrated |
| --- | --- |
| adaptive | served `model`, `effort`, and `candidate_route_id` moving from ladder index i to i + 1 |
| unpinned | served `model` and `effort` equal to the pinned parent session's |
| orchestration-changing | at least two non-parent unit members whose summed wall times strictly exceed the parent's wall time |

A missing observable, a null wall time anywhere in the compared set, or a smoke
that cannot record the frozen `claude_code_subagent_model_unset` observation true
yields *not demonstrated*. An unevidenced demonstration is recorded as not
demonstrated and is never relabeled, and `demonstration_state` is a CAR-004-owned
closed member rather than a score-plane failure code, because a non-scored row
produces no score bundle. [FR-031, FR-031a]

### 7.15 The constraining reading of the authentication mode

`authentication_mode` is the **observed** mode, read over the Claude-side frozen
member enumerated `subscription | api_key` that the experiment-assignment and
successor-capability-freeze contracts carry — never the shared runtime environment
contract's `chatgpt_subscription | api_key`. It is never a `const`: an observed
`api_key` is recorded, and the record is refused **as FR-031 evidence** with the
observed value retained and a refusal reason recorded, so a refused run stays
distinguishable from one that never ran. The remedy is a re-run, not a relabel.
[FR-030c]

### 7.16 The pairwise cache-isolation observable

Cache isolation is discharged by the frozen `observed_cache_isolation` record, one
per **unordered arm pair**, all three across the series, each carrying its status,
this arm's cache-root digest, the paired arm's cache-root digest, and the
disjointness flag. Roots are digests, never filesystem paths. The status set is
read live from the frozen cache diagnostic rather than restated: `observed_disjoint`
is the only status under which a smoke stands as evidence; `observed_shared`
carries `infrastructure_failure` on the infrastructure plane and `unobserved`
carries `required_evidence_missing` on the evidence-boundary plane, both
invalidating the affected smoke rather than warning. The `per_arm_ephemeral_root`
precommitment alone is not the observation. [FR-032, FR-032a]

### 7.17 The eligibility floors

No verdict is reached at all unless every mandatory gate passed: the seven
required gates `role`, `safety`, `grounding`, `mutation`, `tool`, `output`,
`acceptance`, plus the availability gate, with quality floors bound to the frozen
analysis plan and a reliability-guardrail breach resulting in no qualification. An
unmet floor returns `no_verdict`, claim class `no_comparative_claim`, and no
messaging restriction — it does not return `not_dominant`. [FR-019]

### 7.18 The material-dominance margin test

Materiality is reached only on `candidate_dominant`, and the stages run in the
frozen order `eligibility_floors`, `pareto`, `materiality_margin`. Per component
the outcome is `cleared`, `not_cleared`, or `margin_not_computable`; the
denominator is the comparator's value, and a zero denominator yields
`margin_not_computable` rather than an infinite gain. A clear requires the
one-sided lower confidence bound on the relative gain to reach the component's
frozen margin. The four `no_worse_only` components can defeat dominance by being
worse but can never supply it, and no weights enter anywhere. [FR-020, FR-021]

### 7.19 The verdict-to-claim-class mapping

The mapping is total over `dominant`, `not_dominant`, `inconclusive` **and** over
the eligibility-floor no-verdict outcome. Only `dominant` carries a forbidden set
(`efficient`, `optimal`, `best_measured`) and a `true` restriction flag, and its
entry also records that the restriction reaches release wording alone: the static
defaults may still ship for declared operational simplicity. The other three
return `no_comparative_claim` with an empty forbidden set and a `false` flag. A
mixed, tied, incomplete, or statistically uncertain comparison returns
`inconclusive` — never a partial or directional dominance. [FR-022, FR-024,
FR-024a]

## Category 8 — enforcement guards

Stated as required behavior rather than as Claude-side code to copy.

### 8.1 Reserved-partition non-consumption

One entry point must refuse any evidence row — replay **or** smoke — that
references a reserved objective, so the comparison partition held for CAR-011 is
never consumed. The two partition registry entries are produced by the frozen
builder and registered together through the frozen registration path, so
objective-level disjointness is proven rather than declared: a duplicate partition
identifier or a shared objective fails closed. The smoke partition is registered
as `calibration` with `qualification_eligible: false`, and the frozen builder
refuses to invert that pairing. The smoke driver's plan mode derives its objective
list from the registered smoke partition and refuses to emit any objective the
frozen consumption path does not admit, so a reserved objective never reaches an
operator. [FR-025, FR-026, FR-026a]

### 8.2 The control registry is closed at three

The registry check must refuse a registry carrying other than three controls, and
refuse two controls sharing a `control_kind`. The set is closed by FR-001, so a
fourth arm is not the remedy for any disagreement — including the sanctioned
divergence above. [FR-001]
