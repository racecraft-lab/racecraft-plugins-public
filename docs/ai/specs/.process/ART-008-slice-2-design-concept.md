# ART-008 Slice 2 Design Concept — Artifact Freshness

> Produced by the grill-me interview run during `/speckit-pro:speckit-scaffold-spec`
> on 2026-08-24, scoping slice 2 of 2 on branch `art-008-feedback-sweep-slice-2`,
> cut from `main` at `8db22a420` (the slice-1 merge commit, PR #464).
> Slice 1's design concept at `ART-008-design-concept.md` remains the record for
> the whole-spec decisions; this doc records only what slice 2 settles on top.
> **Blind-spot pass:** ran — 3 findings surfaced, 0 set aside

## Goals

- Replace the slice-1 stop report's promise ("draft artifact pages regenerate
  once slice 2 lands") with the real behavior: after a sweep amends planning
  artifacts, the whole draft page set regenerates and the draft pull-request
  description refreshes **before** the re-review stop, so the re-reviewer reads
  pages that match the amendments beside them.
- Detect stale pages on a clean sweep — the recovery path for a run that died
  between amending and regenerating — by a deterministic git-history join, and
  regenerate, refresh, and proceed (slice-1 Q8 carried).
- Keep every deterministic decision offline-testable: the staleness verdict is
  a new read-only runner helper with Layer 4 fixtures, on the exact pattern
  slice 1 set with `sweep-pr-feedback`.

## Non-goals

- No change to the sweep itself: reading, trust filtering, classifying,
  consensus amendment, log rows, replies, and stop-or-proceed are slice 1,
  shipped and untouched.
- No content-hash staleness. Draft pages are agent-authored prose; hashing
  regenerated bytes always reports stale (blind-spot finding 2).
- No new bookkeeping store. The Feedback Sweep Log stays the sole sweep record
  (slice-1 Q6); staleness is derived from it plus git history, never mirrored.
- No second writer of the `Draft PR` row. Gap and shortfall reporting rides
  ART-007's emission machinery, which already owns that row's note.
- No post-implementation review remediation (whole-spec out-of-scope, carried).

## Design Tree (Q&A log)

### Q1 — Staleness primitive
**Recommended and chosen: git-history join.** Pages are stale when any
Feedback Sweep Log row with class `amended` names a `Commit` newer than the
last commit touching `specs/<feature>/artifacts/`. Grounding: slice 1's
quickstart records the log's `Commit` column as "the join key slice 2 uses to
find which pages went stale"; the join is deterministic, offline, and adds no
state. Rejected: generation-stamp comparison (new stamped contract on every
page for marginal precision); a pending-regeneration flag (a second store,
which slice-1 Q6 refused).

### Q2 — Partial-regeneration reporting (blind-spot finding 1)
**Recommended and chosen: reuse ART-007's three sinks.** Regeneration rides the
same emission machinery slice 2 already invokes for the description refresh
(slice-1 Q11), and that machinery owns the PR description's gap rows, the
`Draft PR` row's note ("rewritten whole from the current run's outcome, every
time"), and the run report. The sweep itself still never writes the row — the
create-or-refresh path does, exactly as at plan stage. Rejected: run-report-only
(leaves the row's note describing a stale outcome); stop-on-any-gap (stricter
than ART-007's own fail-open precedent).

### Q3 — Timing on the amended path
**Recommended and chosen: regenerate before the stop.** Same run: amend →
regenerate whole set → refresh description → stop for re-review. The
checkpoint's value is the human reviewing the current plan; fresh pages are the
point. The clean-sweep staleness path (Q1) exists as recovery for a run that
died between amending and regenerating. Rejected: regenerate on the next run
(the re-reviewer reads stale pages — the exact condition the interface sentence
apologizes for).

### Q4 — The regeneration commit
**Recommended and chosen: dedicated docs: commit** staging
`specs/<feature>/artifacts/` alone (e.g. `docs(ART-008): regenerate draft
artifact pages`). Keeps amendment commits reviewable one-by-one, keeps the
bookkeeping commit's workflow-file-path-alone rule intact, and makes the Q1
join exact: the last `artifacts/` commit IS a regeneration. Mirrors the
spec-MOC regeneration precedent (docs scope, no release bump). Rejected:
folding into the bookkeeping or last amendment commit (both break an existing
rule or blur the join).

### Q5 — Whole-set semantics under changed signals
**Recommended and chosen: re-select from the manifest** against the amended
planning record; author every selected page fresh; remove a page on disk that
selection no longer names, reported, never silent. The manifest "is the
routing's source of truth and it grows." Rejected: regenerate the on-disk set
(a newly warranted page never appears); re-select-but-never-remove (carries
pages the manifest no longer justifies).

### Q6 — Where the staleness decision lives
**Recommended and chosen: a deterministic read-only runner helper with Layer 4
fixtures.** The orchestrator gathers the observation (last `artifacts/` commit,
Feedback Sweep Log rows, ancestry facts) and passes it as data; the helper
returns the staleness verdict and the set to regenerate. Mirrors slice 1's
`sweep-pr-feedback` observation-in/verdict-out pattern and extends the same
registry and harness surfaces. Rejected: orchestrator prose only (the one
deterministic decision in the slice would be untestable prompt behavior — the
exact class slice 1 moved into a helper).

### Q7 — The report interface
**Recommended and chosen: outcome lines.** The report states what happened this
run: per-page outcomes (`generated` / `gap` with reason), the regeneration
commit sha, and whether the description refresh succeeded; on a clean sweep
with fresh pages, one line saying pages are current as of the named commit.
Replaces the slice-1 promise sentence that `phase-execution.md:1874` marks as
"an interface slice 2 replaces." Rejected: dropping the sentence (a gap would
go unreported, contradicting Q2); a static sentence (false on gap runs).

### Carried from slice 1, not re-asked
- **Q8 (slice 1):** a clean sweep with stale pages regenerates, refreshes, and
  **proceeds** — no stop.
- **Q9 (slice 1):** regeneration is whole-set, refined here by Q5's
  re-selection semantics.
- **Q11 (slice 1):** the description refreshes through ART-007's
  create-or-refresh path; a draft description is fully fingerprint-protected
  with no editable region, and the refresh rewrites it whole.
- **SC-008 (slice 1) stands:** the FR-015 replies are not weakened on the
  assumption the refreshed description now carries the information.

## Blind-spot findings disposition

1. **Regeneration inherits ART-007's shortfall contract** → resolved at Q2
   (reuse the three sinks through the emission path; no second row writer).
2. **No pure-function staleness precedent** → resolved at Q1 (git-history
   join) and Q6 (deterministic helper).
3. **Estimator false-zero carries to slice 2** → recorded in the slice-sizing
   branch above and as a Plan-phase instruction in the workflow file.

## Open Questions

- **Refresh-failure semantics.** When the description refresh itself fails
  mid-Phase-7 (tool unreachable, identity mismatch), the expectation is to
  inherit ART-007's rule — a failed step stops the sequence where it failed and
  the operator re-run is the recovery — but the interview ended before walking
  it. Suggested next step: settle in Clarify session 1 against
  `phase-execution.md` §create-or-refresh discrepancy handling.
- **UAT shape for the end-to-end loop.** The sweep's consensus routing is
  prompt-level with no automated eval, so end-to-end evidence lands in the
  spec's UAT (whole-spec verification note). What a slice-2 manual UAT can
  exercise before a release refreshes the installed plugin mirrors the slice-1
  T098 limit. Suggested next step: record the discharge path in the workflow's
  post-implementation checklist rather than re-litigating it at Plan.
- **Codex parity detail.** Which slice-2 sentences land in
  `codex-skills/.../phase-execution.md` verbatim versus summarized is left to
  Plan; the Codex autopilot SKILL.md body has **zero headroom** (8000/8000
  words measured 2026-08-23), so any SKILL.md-level change must free words
  first — new behavior belongs in `references/`.
