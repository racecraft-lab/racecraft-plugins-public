## Phase 1: Specify

**When to run:** At the start of the spike. Focus on **WHAT** and **WHY**, not implementation details. Output: `specs/car-001-candidate-route-baseline/spec.md`

### Specify Prompt

```text
/speckit-specify

## Feature: CAR-001 Candidate Route Baseline and Role Contracts

### Problem Statement
SpecKit Pro ships eleven Claude Code agents pinned uniformly to
frontmatter routes (five at opus/max, six at sonnet/max) with no recorded
evidence that these are the right model/effort routes, no qualified fallbacks
when a preferred model is unavailable, and no contract record that would let
later specs evaluate alternatives safely. Before any capability probing
(CAR-002) or scored evaluation (CAR-003) can run, the project needs a dated,
cited research baseline: what each agent's role contract actually is, what
its immutable production route is today, which candidate routes are
role-eligible, and which platform behaviors are documented facts versus
inferences versus proposed policies.

### Users
- CAR-002 through CAR-011 implementers, who consume the manifest, role
  contracts, fixture backlog, capability questions, and go/no-go handoff.
- speckit-pro maintainers, who need an auditable evidence trail for every
  future route decision.
- Plugin consumers (indirectly), whose agents will eventually get
  evidence-backed routes and graceful fallbacks without contract changes.

### User Story (single story — research spike)
As a CAR-series implementer, I need a dated, cited candidate-route and
role-contract research record plus a versioned machine-readable
agent_route_candidate_manifest covering all twelve named agents, so that
CAR-002 can freeze the executable candidate set against probed capabilities
without re-deriving role contracts or re-litigating undocumented platform
behavior.

### Key design decisions (from docs/ai/specs/.process/CAR-001-design-concept.md)
- Two artifacts: Markdown research record at
  docs/ai/research/claude-agent-route-candidates.md PLUS separate JSON
  manifest at docs/ai/research/claude-agent-route-candidate-manifest.json
  (Q1, Q2 — repo convention for machine-consumed data; CAR-002/003/006 bind
  to the JSON programmatically).
- Immutable production comparator pinned to the latest published release tag
  at research time (speckit-pro 2.19.0) plus commit SHA, with agents/*.md
  content hashes recorded for drift detection (Q3).
- Instruction identity = sha256 over the frontmatter-stripped agent body;
  full-file sha256 recorded alongside (Q4 — a pure route change must never
  invalidate instruction identity).
- Fact-table rows carry URL + access date + short verbatim quote (Q5).
- Candidates identified by the four documented aliases (opus, sonnet, haiku,
  fable) with expected resolved IDs recorded alongside; no legacy dated
  snapshots as separate candidates (Q6).
- autopilot-fast-helper contract derived from
  speckit-pro/codex-agents/autopilot-fast-helper.toml as a
  contract-equivalent translation with an explicit platform-field mapping
  table; Claude-only fields (e.g. small maxTurns) get proposed values
  labeled "proposed SpecKit Pro policy" (Q7 — CAR-010 finalizes).
- Fixture backlog entries are requirements-level only: role contract,
  representative tasks, required evidence, pass/fail sketch per agent
  (Q8 — full fixture specs are CAR-003 Work Package B's job).
- Capability questions get stable IDs (CAP-Q1…CAP-Qn) in a dedicated record
  section; the go/no-go handoff is the record's final section.

### Constraints
- Time-boxed: one autopilot run; unverified mandatory facts become no-go
  items or capability questions, never box extensions (Q9).
- Read-only with respect to the plugin: no agent frontmatter, prompt,
  payload, or shipped-default changes; nothing lands under speckit-pro/'s
  allowlisted payload directories.
- Python 3.11+ standard library only for any hash computation; no new Bash.
- Official Anthropic documentation is the only source of platform *facts*;
  anything else is labeled inference, open question, or proposed policy
  (AC-1.2/AC-1.4).
- `fable` enters executor-class candidate sets and is excluded only by
  recorded probe or contract evidence, never product-announcement status.

### Out of Scope
- Live corpus execution, qualification, scoring, or fallback ordering
  (CAR-003+).
- The plugin-owned route-policy manifest and preflight (CAR-006).
- Legacy dated model snapshots as separate screening candidates (Q6).
- Full draft fixture specs (Q8).
- Any claim that a candidate is executable before CAR-002 probing (AC-1.5).
```
