```text
## Feature: CAR-002 Capability Probing, Telemetry Profile, and Exact-Treatment Contract

### Problem Statement
CAR-001 froze 12 agent contracts and 37 candidate routes but left every
executable-route claim deferred behind six capability questions
(CAP-Q1..CAP-Q6): the alias-to-dated-ID bindings for opus/sonnet/haiku/fable,
the undocumented unavailable-model dispatch behavior, and how alias
re-pointing manifests. CAR-003 cannot score outcomes until the executable
candidate subset is frozen from recorded probe evidence and a trustworthy
trace contract exists for the pinned Claude Code client.

### Users
SpecKit Pro maintainers running the CAR evaluation campaign; the CAR-003
through CAR-011 specs, which consume the snapshot, telemetry profile, and
trace schemas as binding contracts.

### User Stories
- [US1] An operator runs the probe tool locally and commits a validated
  runtime_capability_snapshot that answers CAP-Q1..Q6 with recorded evidence.
- [US2] A maintainer reads a versioned telemetry capability profile for the
  pinned client that classifies every field (stable_native / derived /
  derived_from_controlled_configuration / unavailable, nulls preserved).
- [US3] Downstream specs consume route_resolution and exact-treatment replay
  schemas that bind agent, model, effort, instruction hash, mutation
  contract, client version, fast-mode state, and env-override proof.
- [US4] CI deterministically validates the schema contract, the four
  synthetic record classes (success, null, unavailable, misdelivery), and
  the committed snapshot — with zero live model calls.

### Key design decisions (from docs/ai/specs/.process/CAR-002-design-concept.md)
- Q1: Live probing is operator-only; the probe library ships an
  operator-invoked entrypoint; repo/CI tests stay deterministic.
- Q2: One canonical committed snapshot at
  docs/ai/research/claude-runtime-capability-snapshot.json, beside the
  CAR-001 manifest; re-probes replace it, git history preserves priors.
- Q3: The probe matrix dedupes to unique (model, effort) tuples — one canary
  per unique alias for ID binding plus one configuration-acceptance check per
  tuple, ~20 invocations worst case; every candidate route cites its tuple's
  shared evidence.
- Q4: The unavailable-model probe covers BOTH `claude -p --model
  <unavailable-id>` and a minimal subagent-frontmatter dispatch, recorded
  separately per surface, with proof that --fallback-model/fallbackModel is
  unset (the documented native fallback chain would otherwise mask bare
  platform behavior).
- Q5: The four record contracts are one review-visible JSON Schema with
  $defs under docs/ai/research/, validated by stdlib Python in
  claude_trace_schema.py — the CAR-001 manifest-schema + parity-validator
  pattern.
- Q6: Validation is fail-closed at the probe writer (invalid observation
  aborts the snapshot write) AND continuous in CI.
- Q7: Committed raw evidence is the complete --output-format json stdout
  with home paths normalized to <home>, plus a SHA-256 of the sanitized
  payload.
- Q8: Accepted split into 3 vertical slices (WP1 snapshot capture, WP2 trace
  contracts, WP3 synthetic replay validation).

### Constraints
- Evidence authority: platform capability claims only from canonical
  code.claude.com/docs/** or platform.claude.com/docs/** pages; runtime
  probing may narrow availability but never establishes a missing platform
  fact; missing or conflicting documentation fails closed
  (docs/ai/specs/agent-routing-parity-contract.md).
- Consumption gate satisfied at scaffold: amendment PR #362 merged; parity
  validator 18/18 on branch base b57d21a8; the manifest's CAP-Q entries are
  the probe backlog.
- Repo test contract: deterministic unless explicitly operator-only
  (tests/speckit-pro/AGENTS.md); Python 3.11+ stdlib only.

### Out of Scope
- Corpus execution, scoring, statistics, and fallback ordering (CAR-003+).
- Payload or guidance changes; agent frontmatter, prompt, or default edits.
- Live probing in CI or at test time (Q1); per-route 37-invocation probing
  (Q3); unsanitized raw payloads (Q7); Python-only schema definition (Q5).
```

```text
- Declare the 3 work packages (WP1 snapshot capture, WP2 trace contracts,

- The XPLAT-008 docs-surface guard allowlists changed docs/ files narrowly;

## Architecture Notes
- The JSON Schema is the machine contract; the snapshot is one evidence
```

## Atomicity Route

**When this is filled:** After the Tasks phase / gate G5, the autopilot SKILL runs
the read-only atomicity classifier and records its decision here. This is a
**placeholder** until then — leave the cells blank during scoping. The classifier
emits one machine-readable decision; the SKILL is what writes it into this section
(the script never writes a file of its own). This route is recorded only here in the
workflow file — never in the spec map. It is read downstream by the layer-planner and
multi-PR emission work that builds on top of it; recording it now wires no PR creation
or branch splitting on its own.

The decision answers "can this change be split into multiple small PRs safely?" by
inspecting the change's structural seams (independent additive capabilities), not its
line count. Surface the four fields the SKILL extracts from the emitted decision:

| Field | Value | Meaning |
|-------|-------|---------|
| **Route** | | One of `split-PR`, `one-navigable-PR`, `single-atomic-PR`, `branch-by-abstraction`, or `out-of-scope`. |
| **Releasable** | | `true`, or `false` for a destructive-migration or concurrency-sensitive change (a passing CI run does not prove such a change is safe to release). |
| **Signals** | | The decisive detector findings behind the route and releasability reading (may be empty when the classifier abstains). |
| **Warnings** | | Any release-safety warning attached to the change (empty when there is no releasability risk). |

Note: the operator ratified a 3-slice split at scoping (Q8, recorded in the
Scope Budget section above). If the classifier's route disagrees with
`split-PR`, surface the conflict at G5 instead of silently preferring either.

To produce the decision, run the classifier against the feature directory:

```text
runner helper atomicity-route specs/car-002-capability-probing-telemetry
```
