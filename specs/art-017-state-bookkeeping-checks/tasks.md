## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies; establishes baseline and shared fixture.
- **Foundational (Phase 2)**: Depends on Setup; blocks all user-story changes.
- **US1 (Phase 3)**: Depends on Foundational; must run RED tests T007-T010 before T011 production changes.
- **US2 (Phase 4)**: Depends on US1 for atomic rule/intent behavior and shared assertion support.
- **Integration (Phase 5)**: Depends on US1 and US2; must run after final latest-main rebase and generated-artifact refresh.

### Story Dependencies

- **User Story 1 (P1)**: Starts after Foundational. It is the MVP and can be validated independently with shared fixture controls.
- **User Story 2 (P2)**: Starts after US1 because it verifies the final rule/intent/corpus evidence around the newly blocking behavior. It remains independently testable through intent consistency and tracked-pair corpus checks.

### RED -> GREEN Ordering

1. T001-T006 freeze baseline, builder, and source boundaries.
2. T007-T010 add the three isolated negative controls and prove they fail for expected missing `status-evidence` authority.
3. T011-T012 atomically arm the three keys and update their intent verdicts without changing report shape.
4. T013-T015 make US1 GREEN and preserve legacy advisory/report behavior.
5. T016-T020 add tracked-pair corpus evidence and fail-closed discovery behavior.
6. T021-T023 update authored prose and assemble review evidence.
7. T024-T031 rebase, regenerate, check generated surfaces, and run targeted/full verification on one final tree.

### Parallel Opportunities

- No implementation tasks are marked `[P]`. The planned authored work intentionally concentrates in one existing test module, one validator script, and one authored skill file, with strict RED -> GREEN dependencies and an atomic rule/intent change.
- Review-only inspection can be parallelized outside implementation ownership after T013, but edits should remain serial to avoid conflicting writes to `tests/speckit-pro/unit/test-autopilot-bookkeeping-guard.py` and `speckit-pro/skills/speckit-autopilot/scripts/validate-autopilot-phase-coverage.py`.

## Implementation Strategy

3. Complete T011-T015 and rerun the targeted guard test.

1. Deliver US1 as the behavior repair.
2. Add US2 corpus/prose/review evidence without broadening the authored surface.
3. Run the integration phase only after final latest-main rebase/regeneration.

### Parallel Team Strategy

Parallel edit work is intentionally not recommended for this slice. A reviewer can inspect generated-artifact diffs and PR packet traceability while the implementer runs final checks, but source edits should stay serial because the test module and validator change order is part of the evidence contract.
