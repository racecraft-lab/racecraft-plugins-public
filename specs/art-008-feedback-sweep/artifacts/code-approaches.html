Feedback Sweep

The gallery's exporting templates write markdown with different lead sentences and no shared machine-readable marker. The sweep has to tell an artifact export apart from an ordinary review comment. Three ways to recognize one.

Approaches

Each approach carries its own anchor, so the one you choose travels with the export instead of being restated in prose. Read the trade-offs, then choose one.

Which approach should this change take?

Lead-sentence registry in the parser

The read-only helper carries the shipped lead sentences and matches them against the comment body.

# speckit-pro/speckit_pro_runner/helpers/read_only.py
EXPORT_LEADS = {
    'Objections recorded while reviewing this plan.': 'implementation-plan',
    'The approach chosen while reviewing these options.': 'code-approaches',
    'Objections recorded while reading this module map.': 'module-map',
}

def recognize(body):
    # Whole-line exact matches, anywhere in the body, all of them.
    hits = [(i, EXPORT_LEADS[line])
            for i, line in enumerate(body.splitlines(), 1)
            if line in EXPORT_LEADS]
    return hits
Trade-offs for the lead-sentence registry
Pro Con
+No template edits, so no payload regeneration and no cache proofs −An export's lead sentence is prose, and prose can be edited
+Layer 4 fixtures pin every registered lead −Two templates sharing a sentence are ambiguous and need their own outcome
+A future exporting template costs one added string −A reviewer who retypes the sentence gets treated as an export
  • Files touched: 2
  • Payload regen: helper only
  • Fixture cost: low
  • Future templates: one string

Hidden marker in the templates' exports

Each exporting template emits a machine-readable marker the parser matches exactly.

<!-- speckit-pro/artifact-gallery/templates/module-map.html -->
var MARKDOWN_LEAD =
  '<!-- speckit-pro:export template="module-map" v="1" -->\n' +
  'Objections recorded while reading this module map.';

# and in the parser
MARKER = re.compile(r'<!-- speckit-pro:export template="([a-z-]+)"')
Trade-offs for the hidden marker
Pro Con
+Exact and unambiguous; no two templates can collide −Edits three shipped templates plus their payload copies and cache proofs
+Carries a version, so the shape can change later −That file count alone exceeds the slice's budget for a detection detail
+Survives a reviewer rewording the visible prose −Exports pasted before the change ship without the marker
  • Files touched: 3 templates + proofs
  • Payload regen: full
  • Fixture cost: medium
  • Future templates: one marker each

Treat exports as ordinary comments

No recognition at all. Every comment is parsed the same way.

# speckit-pro/speckit_pro_runner/helpers/read_only.py
def recognize(body):
    # Nothing to do: the sweep never distinguishes an export.
    return []
Trade-offs for no recognition
Pro Con
+The simplest parser, and no registry to keep in step −The roadmap's comment-schema fixtures would have nothing to parse
+No template coupling of any kind −The per-phase anchors inside an export are lost
+Nothing to version or migrate −An objection attached to a named phase reads as unstructured prose
  • Files touched: 0 extra
  • Payload regen: none
  • Fixture cost: none
  • Future templates: no cost, no benefit

Recommendation

What planning chose, and what would reopen the question.

Go with the lead-sentence registry in the parser. It is the only option that gives the comment-schema fixtures something real to parse without editing three shipped templates and regenerating their payload copies and cache proofs, which alone would exceed what this slice budgets for a detection detail. The recognition rule is whole-line exact matching anywhere in the body, and the helper reports every matched line rather than the first, so an export pasted below a reviewer's own prose is still recognized.

Two known costs are accepted rather than solved. A lead sentence is prose, so a template that rewords one silently drops out of the registry; the Layer 4 fixtures pin every registered lead precisely so that shows up as a test failure rather than a quiet miss. Two templates sharing a sentence resolve to an explicit template_ambiguous outcome instead of a guess.

Revisit the hidden marker only when a template's export shape needs to change in a way the prose cannot carry, or when a second consumer outside this sweep needs to parse the same block. Neither is true today, and both would justify paying the payload regeneration then.
