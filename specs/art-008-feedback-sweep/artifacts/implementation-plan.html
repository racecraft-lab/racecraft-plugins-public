Week 1 · Wed to Fri

Outbox and replay

Every unsent draft joins a per-device outbox. Replay runs in write order when the connection returns, and a failed push stays queued rather than being dropped.

  • packages/sync
  • apps/editor

Week 2 · Mon to Wed

Conflict resolution

Data flow

Where a write goes, and which part of the path is allowed to run late.

What the drawing says

A draft saved in the editor lands first in the local draft store, which is the only write that happens while the connection is down. When the connection returns the store flushes to sync.pushDrafts, which upserts each draft into the drafts table with its version, and a draft whose version moved on the server is enqueued for the conflict worker. The dashed path is the replay outbox: it holds what could not be pushed, pushes it to the account's other devices once the connection returns, and reconciles each local id back to the server id in the local draft store. The drafts table is the only persistence node here, marked STORE and drawn with a heavier boundary.

Risks and mitigations

Severity is stated in words as well as marked, so a single row lifted out of the table still reads.

Risk Severity Mitigation
Replay order is lost when a device reconnects mid-flush, so a later edit lands before an earlier one. ●●●High Stamp every outbox entry with a monotonic device sequence and refuse a push whose predecessor has not been acknowledged.
The local store grows without bound on a device that stays offline for weeks. ●●Medium Cap the store by total size, evict acknowledged drafts first, and warn in the editor before anything is dropped.
Conflict prompts pile up after a long offline stretch and the author dismisses them all at once. ●Low Group conflicts by document, resolve the newest first, and keep both copies until the author chooses.
