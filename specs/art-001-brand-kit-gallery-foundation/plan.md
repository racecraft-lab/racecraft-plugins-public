# Implementation Plan: Artifact Brand Kit & Gallery Foundation

**Branch**: `art-001-brand-kit-gallery-foundation` | **Date**: 2026-07-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/art-001-brand-kit-gallery-foundation/spec.md`

## Summary

Ship the platform-neutral foundation every gallery artifact consumes, so the four
blocked port specs become mechanical: a canonical marker-delimited brand token
set, a canonical marker-delimited theme-toggle snippet, a 21-entry routing
catalog with a closed five-signal vocabulary declared as data, the single-file
contract and brand-voice references, and one Layer 4 test that enforces all of
it.

The technical approach is deliberately machinery-free. No build step, no
bundler, no expression language, no evaluator, no sync script. Templates embed
two marked blocks verbatim and the test byte-compares the embedded region against
the canonical file, which is what makes hand-copying safe. Triggers are names
checked for form and membership, never evaluated. The catalog stores no artifact
path — it derives `templates/<id>.html` from the identifier, relative to the
manifest's own directory, so the catalog resolves identically from the repository
checkout and from a version-scoped install cache.

One item dominates risk and is not visible from the feature description.
`speckit-pro/artifact-gallery/` only reaches a shipped payload if it is named in
the payload builder's per-platform copy allowlist, and the copy helper is
fail-silent — an unnamed directory produces no error and no output. Without that
edit the entire feature builds green and ships nothing. The plan therefore treats
the allowlist edit plus a source-to-payload reach check as blocking work, not
cleanup.

## Technical Context

**Language/Version**: Python 3.11+ (standard library only) for validation; static
CSS / HTML / JSON / Markdown for the shipped gallery

**Primary Dependencies**: None. No bundler, no Node tooling in the shipped
surface. `pnpm` is required only to regenerate the docs-site test reference page.

**Storage**: Files. `manifest.json` is the routing catalog; `localStorage` holds
the reader's theme override, best-effort.

**Testing**: `unittest` via `run_counted` from `tests/speckit-pro/lib/test_result.py`;
one Layer 4 file, `tests/speckit-pro/unit/test-artifact-gallery.py`, registered
in `tests/speckit-pro/suite-manifest.json`

**Target Platform**: Any modern browser opening a file over `file://` with no
server and possibly no network; Claude Code and Codex plugin installs for the
shipped catalog

**Project Type**: Plugin marketplace repository — shipped plugin payload plus
repository-only validation

**Performance Goals**: N/A. Artifacts are static single files; the test is a
sub-second file scan.

**Constraints**: Renders from `file://` with no console errors; `fonts.googleapis.com`
and `fonts.gstatic.com` are the only permitted external hosts, matched by exact
case-folded equality, and only in resource-loading positions, which are scanned
**default-deny** over every URL-valued attribute rather than by enumeration
(FR-011); artifacts carry none of the FR-027 prohibited constructs — no `base`
element, no scheme-relative reference, no event-handler attribute, no `srcdoc`, no
form target or `ping` — and each carries the in-document policy declaration, since
running without a server means no response header can reach them; WCAG AA audited
per theme independently and complete across every surface pairing; no new Bash
or `jq` surface; the gallery must contain no `.sh`, `.bash`, or shell-shebang
file, because the zero-Bash guard's scan roots include the whole `speckit-pro`
source tree

**Scale/Scope**: 21 catalog entries seeded now, all `status: "planned"`; 0
artifacts ported in this feature; 6 shipped foundation files

**Reviewability Budget**: Primary surface seed/config; plan-phase gate reports

### Budget result and restated justification

**Warning accepted — on a different basis than the spec recorded.**

The greenfield rationale is dead; the replacement rationale is composition and
indivisibility, not size class:

1. **The modify component is two lines.** What forfeits greenfield is adding one
   string to each of two allowlists in `payloads.py`. Every other authored file is
   net-new. Splitting that edit into its own spec would produce a slice whose
   entire diff is two lines plus regenerated payload, and which could not be
   verified independently because nothing would yet exist for it to ship.
2. **The logic surface is one file.** ~580 of ~1,530 authored lines are code, in a
   single test. The remaining two thirds are 21 declarative catalog rows, CSS
   custom properties, prose contract, and a verbatim third-party notice — each
   reviewable by inspection rather than by reasoning about behavior.
3. **The already-rejected split is still rejected, for its original reason.**
   Splitting kit from catalog leaves the second slice's validation importing the
   first slice's marked blocks, so the two would not be Independent.
4. **Four specs are blocked on this one.** ART-002, ART-003, ART-004, and ART-005
   cannot start until the foundation lands; splitting doubles their wait.

**Where this is weakest, stated plainly**: on the raw-authored-lines reading,
~1,530 exceeds the base block threshold of 800. That reading is defensible, and a
reviewer who takes it should require the split rather than accept the warning.
The judgment recorded here is that raw line count over-weights declarative rows
and prose — but it is a judgment, not a measurement, and it is the one part of
this budget a reviewer should push on.

**Fallback split, if the warning is not accepted**: two slices, sequenced.

- **1a — brand kit**: `brand-kit.css`, `theme-toggle.html`, `UPSTREAM-NOTICE.md`,
  the `payloads.py` allowlist edit, plus check groups A (marker drift), E
  (external references), F (payload reach), and G1/G2 (notice file).
- **1b — routing catalog**: `manifest.json`, `SPA-CONTRACT.md`, `brand-voice.md`,
  plus check groups B (shape), C (triggers and closure), D (existence and
  orphans), G3/G4 (attribution headers), H (registration).

This cut defeats the objection that killed the earlier proposal: 1b's validation
reads the catalog, not 1a's marked blocks, so it does not import them. 1b still
depends on 1a for payload reach, which is sequential rather than circular.

**Two corrections to this cut, found in review — it is not executable as first
written.** Check A5 ("every shipped entry's artifact embeds the brand block")
**reads the catalog**, which lives in 1b, so group A cannot be assigned wholesale
to 1a. And suite registration (group H) sits in 1b, which would leave 1a shipping
`test-artifact-gallery.py` unregistered — a test the suite never runs, contradicting
this plan's own Constitution Principle IV assessment. If the split is taken, move
group H into 1a and either move A5 into 1b or scope it explicitly to the vacuous
zero-shipped-entries case.

**Trigger**: take this split if the post-tasks atomicity route or the
pull-request-time diff gate calls for it on evidence, or if a reviewer rejects the
composition argument above.

## Implementation Sequence

Ordered by dependency, matching the PR review order.

1. **Brand kit** — `brand-kit.css` with the provenance header and audited
   contrast table above the start marker, tokens inside it. Inside the marker
   also: the focus-visible treatment, the reduced-motion block, the per-override
   `color-scheme` declarations, and the distinguishable font stacks (FR-004,
   FR-023, FR-024). Anything left above the start marker ships to no artifact.
2. **Theme toggle** — `theme-toggle.html`, with the pre-first-paint `data-theme`
   application, the matching `color-scheme` set for the chosen theme, and the
   `try`/`catch` storage write. The control is a real button, keyboard-reachable
   and keyboard-activatable, carrying an accessible name and an exposed state
   that changes between theme positions (FR-022). The storage **read** validates
   the persisted value against the closed set of theme names, applies a literal
   from that set rather than the string it read, and uses a gallery-namespaced key
   (FR-004). These are decided once here for all 21 artifacts, and the storage path
   is the one place in the shared snippet that handles a value the artifact did not
   author.

   **Open placement decision — where the FR-027 policy declaration lives.** J6
   requires an in-document policy declaration in every artifact. It must be a
   `<meta>` in `<head>`, and the two candidate homes each cost something. Putting it
   in the theme-toggle block reuses an existing marked region that already spans
   head content, at the cost of a block whose name no longer describes its contents.
   A third canonical block names itself honestly, at the cost of a third
   marker pair and a third byte-compare for every port to copy — **and, concretely,
   a third canonical-file check alongside A1 and A2**, since group A asserts each
   canonical file holds exactly one well-ordered marker pair. That consequence is
   named because it is the part a port author would otherwise discover only when
   the suite failed. This plan does not decide the placement; either choice
   satisfies FR-027.
3. **Routing catalog** — `manifest.json`, all 21 entries at `status: "planned"`,
   per `data-model.md`.
4. **Contract and voice** — `SPA-CONTRACT.md` (catalog shape, both trigger forms,
   the stage-then-trigger rule, all five signals' meaning and evidence source,
   the FR-020 attribution rules, the no-`../skills/`-literal authoring rule, and
   the inherited accessibility obligations required by FR-010 — the audited and
   prohibited pairings, the use-of-color rule, the theme-control obligations,
   focus and motion behavior, and the typography rules) and `brand-voice.md`.
   Two properties of this file are load-bearing rather than editorial. Its
   per-signal documentation is one leg of the vocabulary's three-way closure, so
   C8 fails if it documents a name `signals` does not carry or omits one it does —
   write all five, named exactly. And it MUST state that the **validated** shape is
   normative and this document is its explanatory statement (FR-010), so a port
   author who finds them disagreeing knows which governs.
5. **Upstream notice** — `UPSTREAM-NOTICE.md`, captured by direct download, never
   retyped.
6. **Payload allowlist** — add `"artifact-gallery"` to both lists in
   `payloads.py`. **Do this before the first payload regeneration**, or the
   regeneration silently produces nothing and the omission looks like success.
7. **Validation** — `test-artifact-gallery.py` implementing check groups A–J, and
   its suite-manifest registration. Group E and group J are the security surface
   and are **not** written from scratch: FR-011 directs reuse of the URL-validation
   conjunction already in
   `tests/speckit-pro/layer6-efficiency/lib/codex_capability_contract.py`
   (canonical round-trip, no userinfo, no port), the pre-parse character rejection
   in `scripts/release_note_policy.py`, and the unsafe-scheme corpus in
   `tests/speckit-pro/unit/test-release-note-policy.py`. Assembling a second,
   parallel implementation of any of the three is how they drift apart.
8. **Regeneration** — `refresh-release-artifacts.py`, then
   `pnpm --dir docs-site reference:generate`.

Steps 1–5 are independent of one another and may proceed in any order. Step 6
gates step 8. Step 7 depends on 1–6 existing.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| The gallery never ships and everything stays green (FR-018) | Check group F asserts source-to-payload set equality on both platforms; step 6 sequenced before the first regeneration |
| Check group F written too broadly and failing on intentionally unshipped files | F is scoped to `artifact-gallery/` only — `speckit-pro/AGENTS.md`, `CLAUDE.md`, and `GEMINI.md` are shipped by neither payload by design |
| Validation quietly duplicating the signal list, defeating FR-017 | Group C asserts the count `5` plus closure in both directions, and holds no copy of the names |
| Contrast asserted rather than measured | Ratios computed per theme; **four** real failures found and resolved (see `research.md` R8 and R13) |
| An incomplete audit reading as a clean one | The first audit measured one token against a single surface and omitted another token from the dark table entirely; both omissions hid a sub-3:1 pairing. FR-005 now requires the audit be symmetric across themes and complete across surfaces, so absence of a row is a defect rather than an implied pass |
